05 · Glossary

Every acronym and project word used in this guide, one line each. Where a term has a precise definition in the project, the section is given.

Hardware and platform

DSP
Digital signal processor: a second processor in the phone built for wide vector math and low power.
cDSP
The compute DSP of a Snapdragon chip, the one this backend runs on (HEXAGON.md §1).
Hexagon
Qualcomm's DSP architecture and instruction set.
HVX
Hexagon Vector eXtensions: 128-byte vector registers and instructions; "HVX only" means no HMX (HEXAGON_BENCHMARK.md).
HMX
Hexagon Matrix eXtensions: a matrix unit reachable through HexKL; stage 2 of the goals, not used yet.
HexKL
Qualcomm's kernel library that exposes HMX; must be obtained from Qualcomm (plan 0000 §3).
v75 / v79
Hexagon architecture versions. The S25's cDSP is v79; the shipping skel is built for v75 and runs on it (HEXAGON.md §7 rule 1).
8 Elite / SM8750
The Snapdragon 8 Elite chip of the Galaxy S25 / S25 Ultra (HEXAGON.md §8).
VTCM
Vector Tightly Coupled Memory: small, fast memory local to the DSP; 4 MB requested best-effort (HEXAGON.md §2.2).
DMA
Direct memory access: an engine that copies memory (DDR → VTCM) while the vector unit computes.
DDR
The phone's main memory, shared by CPU and DSP.
QuRT
The real-time OS on the DSP; provides threads, HVX locking and the simulator boot image.
PD (unsigned PD)
Protection domain, a process on the DSP; "unsigned" avoids per-device signing (HEXAGON.md §1.2).
pcycles / Mcyc
DSP processor cycles as counted by HAP_perf_get_pcycles; Mcyc = millions of them per token.

RPC and memory

FastRPC
Qualcomm's remote procedure call between CPU and DSP; one call per chunk or token here (~0.26 ms).
IDL
Interface definition language; nntr_htp.idl declares init, forward, forward_debug.
QAIC
The SDK tool that turns the IDL into a stub and a skel at build time.
stub / skel
Generated glue: the stub runs on the host and marshals the call, the skel runs on the DSP and unmarshals it. "The skel" also names the whole DSP library libnntr_htp_skel.so.
rpcmem / dma-buf / fd
Shared memory both processors can address, allocated by RpcmemBuffer, identified by a file descriptor (fd) and handed to the DSP once (HEXAGON.md §1.1).
HAP_mmap
The DSP call that maps a registered fd for the session.
AEE codes
The DSP error numbers (AEE_EBADPARM, AEE_EUNSUPPORTED, …) returned unchanged to the host (HEXAGON.md §1.3).
ABI
Application binary interface; here the op-list wire format, version 4 (HEXAGON.md §1.4).
op-list
The 64-byte header plus 64-byte op descriptors that tell the DSP what to run.
WEIGHTS / KV / ACT / TOKENS / LOGITS
The five buffer ids an op can reference; the first three are mapped once, the last two are per-call arguments.
FARF
The DSP logging macro; lines reach logcat only with a .farf level file (HEXAGON.md §5.3).
SSR
Subsystem restart: the DSP crashing and rebooting.
adb
Android debug bridge, the USB command line to the phone; used only by the person with the workstation.

Model and numerics

LLM, decoder-only
A language model that generates one token at a time from the previous ones; Qwen3-0.6B here.
prefill / decode
Prefill processes the prompt in chunks (128 tokens by default); decode generates one token per call.
tok/s
Tokens per second; prefill and decode are reported separately because they have different bottlenecks.
logits
One score per vocabulary entry for the next token; 151,936 floats for this model.
PPL
Perplexity: how surprised the model is by a known text, lower is better; measured teacher-forced with --eval.
top-1
How many next tokens the model's best guess got right during --eval.
teacher-forced
Feeding the true next token instead of the generated one, so every step is comparable.
W8A8 / W8A16
8-bit weights with 8-bit (or 16-bit) activations; the activations are quantized per token on the fly.
W8_CX
The checkpoint format: int8 weights with one fp32 scale per output channel (per-channel, "CX").
per-token / per-channel
One scale per activation row (token) / one scale per weight output row (channel).
tiled32
The weight byte order: 4 KB tiles of 32 rows × 128 k, so one vector holds 32 rows × 4 k (HEXAGON.md §2.1).
vrmpy / vrmpyacc
The HVX instruction that multiplies 4 int8 pairs per lane and accumulates into int32 lanes.
MAC / GMAC
Multiply-accumulate operation; billions of them.
KV cache
Stored keys and values of every earlier position so decode does not recompute them; lives on the DSP.
GQA
Grouped-query attention: several query heads share one key/value head (16 share 8 here).
SDPA
Scaled dot-product attention, the score-softmax-mix computation.
RoPE
Rotary position embedding, applied to q and k from a precomputed cos/sin table.
RMSNorm / QK-Norm
Root-mean-square normalisation; QK-Norm applies it per head to q and k.
SiLU / SwiGLU
The activation function and the gated block (SiLU(gate) ⊙ up) in the feed-forward part.
down_proj
The last feed-forward matmul, fed by the SwiGLU output; the one with int16 activations.
lm_head
The final projection to logits; tied to the embedding table here.

Float formats and precision words

fp16 / fp32
16- and 32-bit IEEE floating point; hf and sf in HVX instruction names.
qf16 / qf32
Qualcomm's intermediate float formats on HVX; converted back with _equals_ instructions (HEXAGON.md §7).
IEEE-format ops
HVX instructions that operate directly on fp16/fp32 (Vhf_vadd, Vsf_vmpy, …); avoided by rule 1.
RNE
Round to nearest, ties to even.
Von Neumann (jam) rounding
qf32's truncate-and-set-LSB behaviour, why the quantizer needs a magic constant (HEXAGON.md §7 rule 6).
ulp / LSB
Unit in the last place / least significant bit: the smallest step of a number format.
atol / rtol
Absolute and relative tolerance in |d| ≤ atol + rtol·|ref|.
rel-RMS
Root-mean-square of the difference relative to the reference, over a whole tensor.
splat
Broadcasting one value into every lane of a vector.
epilogue
The part of a matmul kernel after the integer sums: scaling and narrowing.

Tools and files

SDK
Hexagon SDK 6.4 (6.4.0.2 in the container, 6.4.0.1 on the workstation), with hexagon-clang 19.0.04 (toolv19).
NDK
Android NDK r26d, baked into the dev image, cross-builds the host harness.
qpm-cli
Qualcomm Package Manager; installs the SDK inside the container after a login.
OrbStack / Rosetta
The container runtime on the Mac and Apple's x86 emulation the simulator runs under.
hexagon-sim
The instruction-level simulator; correctness gate, no DDR model.
SIM_TEST / SIM_PROF / STAT
Line prefixes of the simulator tests, the profile scenarios and their recorded statistics.
E2E / RPC_TEST
Line prefixes of hexagon_e2e_test and hexagon_rpc_test on the device.
.hexw / .hexcfg
The packed weight image and its 12-line shape file (HEXAGON.md §2.4).
.i32
A token file: 32-bit little-endian ids from make_tokens.py.
md5
A checksum used to prove which artifact actually ran.
HF
HuggingFace; the public Qwen3-0.6B download the wizard fetches.
GENIEX / QAIRT / QPN
Qualcomm AI Hub runtimes and reference platform whose rows are the goals in HEXAGON_BENCHMARK.md.

Project words

M1 … M6
Milestones of the backend: M1 round-trip, M4/M5 attention kernels, M6 the HVX optimisation series.
P1 … P5
Phases inside M6: P1 profile baseline, P2 tiled layout (ABI v4), P3 tiled vrmpy matmul, P4 int16 down_proj, P5 attention (planned).
ledger ①–⑮
The follow-up list in docs/superpowers/specs/hexagon-hvx-optimization/07-follow-ups.md; e.g. ④ v79-native skel, ⑫ host logits path, ⑭ SDK 6.4, ⑮ upstream qf32 drift.
handoff
A docs/measurements/<issue#>-<slug>.md file a person executes on the phone and fills in.
gate / rung
One level of the verification ladder in the hexagon-gates skill; rungs 0–4 in the container, 5 on the phone.
state:* labels
The issue state machine: needs-plan → planned → in-progress → review, with needs-measurement → measured on the side (plan 0000 §5).
engine="htp"
The nntr_config.json switch that sends the whole model to the DSP (HEXAGON.md §5.4).
fallback
The app running on the CPU when the DSP path is unavailable; a safety net, not a strategy.
harness
hexagon_e2e_test / hexagon_rpc_test: the standalone device programs used for measurement and debugging.
reference
hexagon_ref_run on x86, the accuracy oracle.
