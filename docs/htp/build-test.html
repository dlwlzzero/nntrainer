Build & test

The HTP backend has two halves that ship separately: the app on the ARM side and the skel (libnntr_hvx_skel.so) on the DSP. This page builds both, puts them on the phone, and runs the checks that need no phone. How the halves talk is on Communication; the code layout is on Software.

1. Environment #

Every build below starts from one shell:

source tools/htp/env.sh

It sources the Hexagon SDK (6.4.0.1 is the verified version) and sets HEXKL_ROOT, the HexKL package that holds the DSP matmul library. Override HEXAGON_SDK_ROOT, HEXKL_ROOT, HEXKL_SDK_VER or HEX_ARCH (default v79) before sourcing it. ANDROID_NDK must be exported for the app build.

2. Build the DSP skel #

HEXKL_SDK_VER=6.4.0.1 test/htp/build.sh
# → test/htp/build/libnntr_hvx_skel.so
# last line: UNDEFINED SYMBOLS OK (<n> runtime imports)
  • Runs qaic on test/htp/nntr_hvx.idl, then compiles the skel entry files and the hmx/ and hvx/ kernels (the SRCS list) with hexagon-clang -mv79 -mhvx -mhvx-length=128B -O3 and links HexKL's libhexkl_micro.a.
  • Pin HEXKL_SDK_VER. Left unset, the script takes the newest version under $HEXKL_ROOT/lib, which may not be the verified one.
  • Undefined-symbol check. A DSP shared object links even with unresolved symbols; the phone then refuses to load it with 0x80000406. The script fails the build on any import the DSP image does not provide, so a forgotten source file is caught here instead of on the phone.
  • Extra defines go in HEX_EXTRA_CFLAGS.

3. Build the app #

Applications/CausalLM/build_android.sh --htp           # first build
Applications/CausalLM/build_android.sh --htp --cache   # rebuilds

--htp regenerates the ARM stub from the IDL, finds libsdkl.so in the HexKL package, and configures nntrainer with -Denable-htp=true. It does not build the skel.

4. Put it on the phone #

  • The skel goes into a directory on ADSP_LIBRARY_PATH; the app's libraries go on LD_LIBRARY_PATH.
  • Use the phone's own libcdsprpc.so, never the SDK's link-time stub.
  • Record the md5 of the skel and the app libraries you pushed; a measurement is tied to that pair.

5. App and skel must match #

Any change to the IDL or to a DSP source means rebuilding the skel and pushing it. An IDL change also means regenerating the stub, which the app build does. A mismatch fails loudly; the message tells you which way:

you seeit means
0x80000406 when the session opensthe skel does not load, usually an undefined symbol (§2)

configure error: the stub is older than nntr_hvx.idlIDL changed, stub not regenerated

6. Host checks: no phone needed #

Two scripts run DSP code on the workstation. Run both before any device work.

6.1 Kernel checks #

test/htp/host/run_host_checks.sh

Compiles the DSP sources with the host gcc against stand-in headers (threads on pthreads, the DMA engine completing at once). Needs no SDK. The HMX and most HVX arithmetic are scalar stand-ins, so these checks do not verify the hardware's arithmetic; they verify everything around it:

  • MoE routing, buffer reuse, scatter and the VTCM layout. A DMA into a buffer that is still being read shows up as a wrong result.
  • The option word, the DMA plans, the worker pool, the FC and conv-block layers.
  • The per-token entry's op table and forward loop.
  • The single-token kernels (small ops and decode attention): their real HVX sources, compiled on an emulation of one IEEE op per lane, must match a scalar spec byte for byte.
  • The decode GEMV kernel on the SDK's x86 HVX emulation, when that library is installed. Two deliberate mutations of the kernel must make it fail, or the check is blind.

6.2 End to end, in process #

test/htp/host/run_inproc_e2e.sh      # prints INPROC E2E PASS

Builds nntrainer with -Denable-htp=true -Dhtp-inproc=true into build_htp_host/, with the DSP skel compiled for the workstation and linked into the process. Then it runs a tiny LFM2-MoE fixture (16-token prompt, 8 greedy tokens) through the real ARM-side HTP path. Needs the SDK's headers and qaic; no phone, no HexKL.

  • Proves: the session and option wiring, the call marshalling, and that every MoE call's input and output is bit-identical to a committed golden and between the two decode paths; the tokens match the CPU path.
  • Cannot prove: tok/s, transport, DMA, or the HVX/HMX arithmetic bits.

7. Adding a DSP method #

  1. Append it at the end of nntr_hvx.idl, so every existing method keeps its id.
  2. Implement nntr_hvx_<name> in the skel file of its group. Validate every length and handle and return AEE_EBADPARM on a mismatch: the ARM side is a trust boundary for the DSP.
  3. Add any new .c file to SRCS in test/htp/build.sh; the undefined-symbol check catches a forgotten one.
  4. For per-stage timing, add a _timed twin, not a flag.
  5. Rebuild and push both halves.
  6. If the app depends on the new method, make it fail loudly on an old skel. The option echo on the first MoE call is the model to copy.

8. The rest of the ladder #

After the host checks come the device steps: the on-device kernel test, then a full-model run on the phone. The order and what counts as a pass are in Measurement §3.
