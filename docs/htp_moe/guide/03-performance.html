What each measurement decided

#77 — first handoff (2026-09-21, R3CY205ZMND, filled at e8b930ad)

The control runs put the PR head on a second phone under the project's fixed protocol (prompt 512, 8 threads, greedy): the NPU model decodes at 17.0–21.3 tok/s and the CPU model at 46.4–54.1, so the NPU is 2.7× short of the 50 tok/s goal at gen 512 while the CPU clears it at gen 64 and 512 and misses it at 1024; NPU prefill is the one place the HTP wins (403–541 vs 231–336). Because the sitting ran on the second unit (~7 % apart in DSP clock), the numbers were recorded unit-tagged and did not replace the provisional "now"; the anchor sitting on R3CY10WM83Y is #91. Measurement A (the profile build) showed that MoE plus the dense FCs are 92 % of the NPU token and that the MoE on the NPU costs ~2× the CPU path per token, which ranks the levers: the MoE call first, round trips second, lm_head not first (the NPU already wins there). Measurement B settled wall 3: the transport stays at 527.7 µs when the DSP is kept hot (level 3), so it is marshalling, not wake-up; the fix is prebound arguments and persistent staging on plain FastRPC (#88), not a resident worker yet. Measurement C rewrote wall 2: the DMA engine reaches 72–117 GB/s in isolation on the same arena and skel, workers and the bus vote change nothing, so the 16–18 GB/s seen inside the layer call is a property of how the call uses the ring, to be instrumented in situ (#87, LEDGER rule 11). The two-reader probe's DSP side was invalid (rule 12, #90); its CPU side showed −41 % under contention, so any CPU+NPU split pays less than the sum. Three protocol defects were found and filed: the generation(last 64) line never prints for this model (#89), compiled artifacts are not byte-reproducible across build paths (rule 14), and NNTR_HTP_PROFILE=3 inflates [M0-PROF] ffn= ~5× (rule 15). 77-first-handoff.md Results and Deviations; LEDGER §1 rules 11–16, §2 verdicts ①–④; BENCHMARK.md Log 2026-09-21

PR-author rows (2026-09-16/17 and 2026-09-21, not handoffs)

These come from the upstream PR's own documents and set the starting point: with the MoE FFN on the HTP the PR measured decode 20.8 tok/s against a CPU 48 (doc 49 §1), and its decode anatomy (doc 48 §3) named the three walls. A later run with conv in_proj also on the HTP fell to 16.5 tok/s with no code cause and no control run in the sitting (doc 50 §3.4), which is why every sitting in this project starts with the control binary (LEDGER rule 9).
