What it means, in plain words. #113 had left one lever inside the MoE call: the vector unit reading the 22 MB of expert weights straight out of main memory tops out near 23.5 GB/s, while the DSP's DMA engine can move the same bytes at 31 GB/s or more. #117 built that: while the vector unit works on one expert, the DMA engine copies the next expert's two weight matrices (gate/up 3.5 MiB, down 1.75 MiB, one descriptor each — the f2 shape #100 certified) into the DSP's on-chip memory (VTCM), into two slabs that alternate by expert; the one-row loop then reads the on-chip copy and its l2fetch lead is switched off, because there is nothing left to prefetch. Every push is a whole matrix, every slab is reused only after the pool run that read it has finished, and a host-side scoreboard proves that schedule. On the phone the multiply time per call fell from 932 to 676 µs (the gate was 760) with the engine busy 90 % of the call at 32–34 GB/s, the round trip fell from 190 to 92 µs (an unexpected second win: the extra transport #100 had booked as "the GEMV path's own cost" was really the arena read's), and decode rose 29–32 % at every length with byte-identical text, 36 runs out of 36, in a warm sitting and a cooled one. Prefill is untouched by construction (the feed runs only at M = 1; the M > 1 DSP time moved 0.04 %); its tok/s column read −8.5 % at G=1024 in sitting 2, which the handoff traces to A's own two runs (528.9 first after the cool-down, 401.9 = A0's run 2 to the digit) — rule 27's run-order spread, so the prefill gate passes on its tie-breaker. One honest caveat travels with every number here: this is a different phone, and its DMA engine is 19 % faster than the one every earlier sitting used (37.3 vs 31.2 GB/s on the untouched anchor cell) while its vector unit reads DDR at the same rate (A's mm 931.9 vs #113's 937.0). So the mm half of the gate holds as measured on this unit and would miss by ≈ 6 % on the other; the decode half (B ≥ A at all three G, text = A) transfers, at ≈ +10 % instead of +30 %. Both sittings passed, so PR #118 flipped the default (HVX_GEMV_M1_FEED 1u; merged as d79c0efe): an unset run now prints [HTP] moe m1 gemv: on (applied=0x303e1) lead=192KB rows1=1 feed=vtcm source=default, and NNTR_MOE_HTP_GEMV_FEED=0 reaches the arena read (0x103e1, feed=arena) as the next sitting's A0.
