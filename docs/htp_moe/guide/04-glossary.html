4. Glossary — every acronym and term on these pages

definitions as used in plans 88, 101 and 105, docs/measurements/88-moe-call-marshalling.md, contract docs/plans/0001-…, LEDGER.md, BENCHMARK.md, doc 49 §3–§4 and the code under nntrainer/tensor/htp_backend/.

A/B
Two variants run in the same sitting on the same phone; only their ratio is a verdict (LEDGER rule 9).
acc, acc_read
The HMX accumulator (64 rows × 32 int32) and the instruction that copies it out to VTCM; the HMX stalls while it is read. Profile column acc.
adb
Android Debug Bridge: the USB tool that pushes files to the phone and runs commands on it. Agents never run it.
0x80000406 (skel does not load)
FastRPC error from remote_handle_open_domain, logcat dlerror RX VA 0xFFF00000 outside ELF segment: the DSP loader refused the skel image. On this project it meant undefined project symbols in the skel (#97); not a segment-layout bug. See page 1 §2.
AEE_EBADPARM (0x8000040E)
FastRPC's "bad parameter" error; on this project it almost always means a skel that loaded but does not match the app's IDL — a stale skel or app (rule 3). Distinct from 0x80000406 above and from [Engine] htp Context is not registered (app-side: the htp context exists only in an ENABLE_HEXKL build, engine.cpp:70–72).
AH tile
"Activation, HMX order": 64 rows × 32 k-values of u8, 2048 B, the layout of the activation operand the HMX reads.
arena (ION arena)
3840 MiB of ION memory in 256 MiB chunks, mapped once into the DSP, holding all 1408 expert weight matrices in WH order.
ARM
The phone's CPU cores (Cortex big.LITTLE), where the app and everything not on the DSP runs.
blocked wait / dry wait
A DMA wait that found its descriptor still in flight (blocked) vs one that returned at once; counted per call by the ring trace (waits=… (blocked …)).
bus vote
A request the DSP makes for DDR bandwidth (40 GB/s at session open); the novote skel drops it. Worth ≤ 4 % in #77.
cache maintenance (clean / invalidate)
What the FastRPC driver does to a cached ION buffer on every call so the DSP sees the ARM's writes (clean = write the cache back to DDR) and the ARM sees the DSP's (invalidate = drop stale lines); it covers the whole buffer, not the bytes used. With the old 4 MiB staging pair this was 245.8 µs of every decode call (#88).
cDSP
The compute DSP domain of the Snapdragon; the FastRPC session opens with _dom=cdsp.
cold / warm call
A single-shot MoE call after the ~0.6 ms FastRPC gap (profile level 2) vs the last of five back-to-back repeats (level 3); the DMA trace is printed for both.
control (variant A)
The unchanged reference binary that opens every sitting.
conv block / causal_conv1d
LFM2's non-attention mixer: two FCs around a short depthwise convolution with two gating multiplies.
CPU control
The q40 model on the CPU: the tok/s floor the NPU must beat.
DCVS / DVFS
Dynamic clock and voltage scaling: the DSP may lower its clock when idle; a candidate cause for run-to-run drift.
decode
Generating tokens one at a time after the prompt; M = 1 everywhere.
DDR (LPDDR5X)
The phone's main memory; 34–38 GB/s measured for one reader, the speed limit of decode.
dequant / requant / quant
int32 → f32 with scales (dequant), f32 → u8 for the next matrix (requant), the first f32 → u8 of the activation row (quant).
descriptor
One DMA job: row bytes × row count at a source stride, to a VTCM address (with its own destination stride). An M=1 MoE call pushes 46 (4 experts × 11 + 2 copies).
descriptor list (chunk list)
The ordered 46 descriptors and 30 wait points one M=1 MoE call issues on the ring, over 32 arena regions; recorded by the DMA ring trace and replayed by MoeChunkReplay. Row h of #94 found this list alone runs at 40 GB/s where a probe of the same per-descriptor shape does 107 (LEDGER rule 19, #100).
DMA
Direct memory access: the DSP's copy engine, driven by descriptors (2D: row bytes, stride, row count) through a ring; how weights get from DDR to VTCM.
DMA ring trace ([HTP-DMA], DMA ring:)
PR #93's bookkeeping of every push and wait on the ring inside a timed MoE call, read back through moe_dma_trace_read and printed by the ARM; off unless NNTR_HTP_PROFILE ≥ 2.
dma_replay / MoeChunkReplay
A skel entry and device gtest that push the M=1 call's descriptor schedule with no compute in between, to time the engine on the in-situ list alone; 11 cells (workers × pacing × competitor × fresh pages × gap). Its content check failed in #94 because it wrote VTCM packed instead of strided (#99); the timings stand.
DMA_PROBE / DmaProbeShapes
The isolated arena-rate gtest (16 lines: four shapes × workers 1–4). Shape iii = 8 KiB × 64 rows @ 56 KiB stride is the gate/up chunk geometry; 106.9 GB/s cool / 88.8 hot in #94 (rule 18).
drain
Profile column: time spent waiting for a DMA transfer that was not hidden behind compute.
DSP
Digital signal processor; here the Hexagon core inside the HTP.
dspqueue
Hexagon SDK's low-latency ARM↔DSP queue; deferred alternative to plain FastRPC calls.
expert
One of 32 small FFNs in a MoE layer: gate_up [2048 × 3584] and down [1792 × 2048], 5.25 MiB in int4.
FastRPC
Qualcomm's remote procedure call from ARM to DSP; one call = marshal arguments, wake a DSP thread, run the skel function, return.
FC (fully_connected)
A dense matrix multiply layer (in_proj, out_proj, q/k/v/o, dense FFN).
FFN
Feed-forward network: the gate/up → SwiGLU → down block of a layer; MoE or dense.
GEMM / GEMV
General matrix–matrix / matrix–vector multiply. Decode is GEMV (M = 1).
FWHT / Hadamard rotation
Fast Walsh–Hadamard transform: an orthogonal ±1 butterfly that spreads a vector's values evenly; #95 plans a 256-point one before the down-projection requant, with the inverse folded into the weights offline.
gather / scatter
Gather: bring a block's activation rows (and scale/zp) to where the HMX reads; scatter: out[row] += weight · result, the weighted sum of the experts.
gen (G)
Generation length in tokens: 64 / 512 / 1024 in every handoff.
greedy decoding
do_sample: false; the argmax token every step, so runs are repeatable.
handoff
A measurement document (docs/measurements/<issue>-<slug>.md) the user runs on the phone in one sitting and fills in. Its binaries must be rebuildable from the named commits on any workstation; a staging path is not a deliverable (LEDGER rule 22).
HexKL
Qualcomm's kernel library exposing the HMX (libhexkl_micro.a on the DSP, libsdkl.so on the ARM).
HMX
Hexagon Matrix eXtension: the matrix unit; one instruction multiplies a 64 × 32 u8 tile by a 32 × 32 i4 tile into the accumulator.
host / dsp / transport
Profile columns: host = the call as timed by the ARM; dsp = as timed by the DSP; transport = host − dsp, the round trip (87.9 µs per decode call since #88). Transport and host drift between sittings like tok/s (401 vs 649 µs on identical sources two hours apart), so they are compared only as an A/B inside one sitting; only dsp is comparable across sittings (LEDGER rules 20, 23).
HTP
Hexagon Tensor Processor: Qualcomm's name for the NPU (DSP + HVX + HMX + VTCM).
HVX
Hexagon Vector eXtensions: the DSP's 1024-bit SIMD unit; a thread must own an HVX context to use it. The session sizes its worker pool from the context count qurt_hvx_get_units() reports (6 lanes on v79 per plan 105; older text said four).
IDL / qaic / stub / skel
The interface file nntr_hvx.idl; the generator; the ARM-side caller code; the DSP-side receiver library libnntr_hvx_skel.so.
issue-bound / feed-bound
Whether a loop is limited by how fast the core can issue its instructions or by how fast the data (here the arena weights) arrives; #105's microbench MoeM1GemvFeedVsCompute tells them apart for the GEMV.
int4 (i4) / u8 / int32 / f32
4-bit signed weights; 8-bit unsigned activations; 32-bit integer sums; 32-bit floats.
ION
Android's shared-memory allocator (rpcmem): buffers both ARM and DSP can map; uncached on the DSP side.
KV cache
Stored keys and values of past positions that attention reads at decode.
l2fetch
DSP instruction that prefetches a 2D region into L2 ahead of vector loads; non-blocking, up to 3 queued per thread, lower priority than real loads.
l2fetch lead
How far ahead of use a lane prefetches its weight columns. The GEMV issued each column's l2fetch right before that column's loads (lead 0); #105 / PR #107 lets each lane fetch its next block of columns while computing the current one (HVX_GEMV_PF_LEAD_KB: 0 / 64 / 192 KB = variants B1 / B2 / B3; too long a lead could evict useful lines from L2).
libnative (HVX emulation)
A C implementation of every HVX intrinsic shipped with the Hexagon tools; PR #107 builds the real GEMV source on x86 against it, so its bit-identity is checked on the workstation, not only on the phone.
LEDGER / BENCHMARK
docs/htp_moe/LEDGER.md: rules learned on silicon, verdicts, open items; BENCHMARK.md: goals and every measured row.
LFM2.5-8B-A1B
The model: 8 B parameters total, ≈ 1 B active per token (top-4 of 32 experts).
lm_head
The final projection to vocabulary logits; tied to the embedding (same matrix, 128000 × 2048).
M, K, N
Matrix shapes: M rows of activation, K reduction length, N output columns. Expert gate_up: M × 2048 × 3584.
M0-PROF
NNTR_M0_PROFILE=1's ARM-side per-MoE-layer stage line.
marshalling
Packing call arguments for FastRPC; #77 B's first name for the transport cost. #88 showed the arguments themselves are 464 bytes and cheap; the cost was cache maintenance on the staging buffers plus the poll window.
M=1 GEMV path (NNTR_MOE_HTP_M1_GEMV, moe_set_opts)
PR #86's branch inside the MoE kernel: at M ≤ 4 the four experts run on the HVX GEMV from the arena with no DMA and no HMX; enabled per session by the IDL method moe_set_opts; default off (#101, in progress, flips it on with =0 as the opt-out). Measured in #94 as variant C: +6.2 / +7.7 / +1.7 % decode, text identical, dsp 1414 → 1044 µs but mm 783 → 975 µs (LEDGER ⑯).
md5
Checksum used to identify every pushed binary and model file.
mm
Profile column: HMX instruction issue time, timed by difference.
MoE
Mixture of experts: a router picks a few experts per token; here top-4 of 32 in 22 layers.
NDK
Android Native Development Kit: the ARM cross-compiler (r30 here).
NPU
Neural processing unit; in this project the HTP.
packed vs strided (VTCM writes)
Where a DMA descriptor's rows land in VTCM: strided = destination stride equals the source stride (the kernel: an expert's eight gate/up chunks tile one 3.67 MB window exactly once); packed = destination stride equals the row size (the probe, and the replay before #99: rows contiguous, chunks overlapping in 569 KB). The DDR read is the same either way; only the write geometry and the checksum footprint differ (plan 99 §3).
paced / unpaced replay
pace=1 replays the descriptors at the traced in-situ wait points (reproduces the in-call 15.6–18.6 GB/s); pace=0 issues them as fast as the ring allows (40.2 GB/s in #94, the row-h number).
one-row GEMV (gemm_row1)
#105 / PR #107's inner loop for a single activation row: one accumulator, 8 vrmpy per weight tile, the same accumulation order as row 0 of the four-row loop (gemm_rows4), so the int32 sums are identical by construction. The four-row loop at one row issued 32 vrmpy per tile, 24 of them wasted, in a pattern the v79 manual lists as an accumulator stall (36 vs 11–13 packets per tile). (LEDGER ㉒ spells it gemm_rows1; the plan and the PR use gemm_row1.)
one call per token
The target shape: the whole layer stack resident on the DSP so a token costs one FastRPC round trip (LEDGER ⑨).
PD (unsigned PD)
Process domain on the DSP; "unsigned" lets a non-signed skel run.
poll QoS (qos_mode=2) / poll window
After sending a call the ARM thread can poll — check for the reply over and over, fast but keeping a core busy — or sleep until an interrupt wakes it, cheap but slow to wake. The poll window is how long it polls before sleeping: 5000 µs since PR #103 (NNTR_HTP_POLL_US, was 100 µs, which every ≈ 1.4 ms decode call outlived; worth 67.6 µs per call in #88). qos_mode=2 in the profile header = poll accepted; 1 = the driver refused the value (10 000 is refused) and fell back to PM QoS.
per-token budget
LEDGER §2's split of one decoded token into MoE DSP time, transport and "outside the MoE call", derived from tok/s minus 22 × the profile row — an estimate, not a measurement (42.0 ms at G=512 on #88 B: 30.4 / 1.9 / ≈ 9.6).
prebind
Plan 88's conditional step (per-layer handles bound once); not built, because #88 met the ≤ 0.1 ms gate without it.
PR (#4327)
The upstream pull request this branch is frozen from; its docs are docs/htp_attention/*.
prefill
Processing the prompt (512 tokens) in one pass; M ≫ 1; the −5 % gate on every change.
profile build (--profile)
An app build that prints per-node totals; never read for tok/s (rule 1).
Q4_0
4-bit block quantization (32 weights per scale) the CPU kernels read.
QS4CX / QS4CX_WH
4-bit per-channel quantization; the WH variant is pre-arranged in HMX tile order and has no CPU path.
region (arena region)
One 256 MiB ION chunk of the arena as seen by the DMA engine; the M=1 list touches 32 per call (regions=32 in the replay is its fresh=1 rotation pool, not the expert count — plan 99 §3).
row h
The eighth row of plan 87's wall-2 attribution table, added by the device in #94: the real chunk list is slow on its own (40 vs 107 GB/s), ≈ 60–70 % of the isolated-vs-in-situ gap. Fix issue #100.
RMSNorm
Root-mean-square normalization, before each mixer and each FFN.
RoPE
Rotary position embedding applied to q and k in attention.
router / top-k
The small FP32 matrix and the sigmoid + bias ranking that choose 4 experts and their weights.
RPC
Remote procedure call; see FastRPC.
RSS (peak memory)
Resident set size the app reports at the end of a run, in KB.
rung / gate
The verification ladder: 0 format, 1 host build + checks, 2 skel, 3 Android app + device gtest, 4 device handoff.
SDK (Hexagon SDK 6.4.0.1)
Qualcomm's DSP toolchain.
SiLU / SwiGLU
silu(x) = x · sigmoid(x); SwiGLU = silu(gate) · up, the FFN's non-linearity.
size-class staging
Upstream's fix (fb0f02b9, in htp_moe via PR #103): one cached ION staging buffer per power-of-two size from 64 KiB, picked per call, so a decode call rides a 64 KiB pair instead of the 4 MiB pair the prompt grew — the driver's whole-buffer cache maintenance shrinks with it (245.8 µs per decode call in #88). Both classes stay allocated (+0.3 % peak RSS).
staging: line
Profile line (level ≥ 2, since PR #103) under each MoE row: the size classes the call rode, ion=y|n, rpc allocs (process-wide count of shared buffers; must not grow with calls) and the argument bytes copied outside ION (464 at decode).
same-unit drift
How much one phone's tok/s moves between sittings with no code cause: up to −16 % (NPU) / ±9 % (CPU) per cell in #94 vs #77 while the DSP profile columns moved ≤ 4 % (LEDGER rules 9, 20). Recorded as a note, never as a verdict.
sitting
One uninterrupted session on the phone; the unit within which numbers are comparable.
SNR
Signal-to-noise ratio in dB between two paths' outputs; NNTR_L2_DIFF's accuracy measure, the gate for #95.
SMMU
The IOMMU that maps ION buffers into the DSP's address space.
stage
Profile column: DMA copies of the activation in and the output out of the ION buffers.
thermal_zone0
The phone's SoC temperature sensor the handoff samples at each checkpoint (29 °C cool → 51–55 °C after the twelve A cells in #94); probe readings are quoted with it (rule 18).
transport (wall 3)
The FastRPC round trip of one call, host − dsp. Closed as a wall by #88 (401.3 → 87.9 µs per decode call, 1.9 ms per token). Only comparable inside one sitting (rule 23).
tok/s, TPS
Tokens per second; the app prints "TPS".
UND symbols / undefined-symbol guard
UND is readelf's mark for a symbol a shared object imports rather than defines. A Hexagon skel legitimately imports ~46 runtime symbols (HAP_*, qurt_*, libc…) that the DSP image resolves at load; a project symbol left UND (a .c missing from build.sh) links fine and fails only on the device with 0x80000406. Since PR #98 build.sh checks this and prints UNDEFINED SYMBOLS OK (<n> runtime imports) (LEDGER rule 17).
unit
A specific phone, identified by its adb serial. Since 2026-09-22 no particular unit is required (contract §12): a handoff names none, the filled handoff records the one used. So far every nntrainer row ran on R3CY205ZMND (#77, #94, #88); the PR author's rows are from R5KL30G6MLT. Two S25 Ultras were 6–8.6 % apart on one binary in an earlier project, which is why numbers are compared only inside a sitting (rule 13).
variant A / B / C
A = the unchanged control binary that opens every sitting; B, C = the variants read against it. In #94, C was the same binary with the M=1 GEMV switch on; in #88, B was PR #103 and C was B with the poll window back at 100 µs.
v79
The Hexagon architecture version in the Snapdragon 8 Elite.
vrmpy
HVX multiply-accumulate of four u8 × i8 products per lane; the GEMV's inner instruction.
VTCM
Vector tightly-coupled memory: 8 MiB of on-chip SRAM the HMX reads from; filled only by DMA.
wall
One of the three measured limits of the decode MoE call: HMX 64-row tile, weight DMA rate, FastRPC transport.
WH tile
"Weight, HMX order": 32 k × 32 n int4, 512 B, the layout the HMX (and the HVX GEMV) reads.
worker pool
DSP threads with HVX contexts (one fewer than the contexts the DSP reports; the calling thread is the extra lane) that run epilogues, requant and scatter behind the HMX, and the GEMV's column units.
zp (zero point)
The offset of an asymmetric u8 quantization, per row, alongside its scale.
