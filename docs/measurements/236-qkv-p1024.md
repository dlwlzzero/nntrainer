# Measurement 236: the hybrid at P1024 with the qkv / o_proj FCs in 512-row chunks

## Why

In #225's sitting the hybrid B died at P1024 in its first attention
layer: `nntr_hvx_mm_u8i4_layer failed: err=0x80000600 (M=1024 K=2048
N=3072 handles=3)` (`AEE_ERPC`), because the FC entries stepped by
`fcMaxRows` (1920 rows at K = 2048) while every other prefill call was
already in 512-row chunks (LEDGER rule 64). #236 makes every M > 1 FC call
step by `min(fcMaxRows(K), prefillRows())` (plan
`docs/plans/236-qkv-fc-prefill-chunks.md`); host-proven bit-identical.
This sitting answers whether B now loads and runs P1024 on the config of
record, at what speed against Bfb (the fallback that stood in for it).

| gate | read from | pass |
|---|---|---|
| G1 loads | `B_P1024_G64_r1/_r2`, `B_P1024_G512_r1`, `B_P1024_G1024_r1` | `prefill:` and `generation:` lines; one `[HTP] fc wh: file=…fcwh.bin … heap_kib=<n> requant=0`; no `0x80000600` / `0x80000402`; not VOID |
| G2 prefill | the same rows | P1024 prefill ≥ −5 % of #225's Bfb: G64 ≥ 630 (663.2), G512 ≥ 618 (650.6), G1024 ≥ 617 (649.7); read beside the anchor (B P512 G64 vs #225's 727.3, and vs A′ P512 G64 of this sitting) |
| G3 decode | the same rows | ≥ Bfb's 52.03 / 51.51 / 48.74, read through the anchor's drift (#225's B P512 G64 decode 55.17); the CPU of record (#225 A) 47.58 / 48.82 / 47.41 |
| G4 chunked | `prof_B_P1024` | `M>1 FC` K = 2048 N = 3072 (qkv) and N = 2048 (o_proj): `calls` × 512 = `rows` (every call 512 rows); expected `calls=12 rows=6144` each (6 attention layers × 2 chunks; the host fixture showed one more 512-row call on the N = 2048 row, so a 13 / 6656 is read, not failed) |
| T2 texts | `logs/texts.txt`, `logs/loops.txt` | recorded, not gated: B P1024 texts ≠ CPU is expected (rule 39); a loop where #225's A has none is noted; the user approves |

## What to expect (arithmetic, not measured)

* **A′ P1024 G64 (control):** dies exactly as in #225 (same binary set),
  `VOID` with `0x80000600` — that reproduces the failure in this sitting.
  If it loads instead, the failure was not deterministic and B's result
  says less; say so under Notes.
* **B at P1024:** 12 more FastRPC calls per prefill (6 attention layers ×
  qkv + o_proj) at ≈ 0.4 ms ≈ 5 ms on a ≈ 1.5 s prefill (≈ 0.3 %), and
  ≈ 24 MiB more weight DMA (< 1 ms). Prefill should be at or above Bfb's
  (B runs the attention FCs and the dense FFN on the NPU, Bfb on the CPU)
  — #225's P512 had B 727 vs Aoff 527. Decode is B's (CPU FCs at M = 1),
  unchanged by this change; Bfb's decode is the same path, so ≈ equal.
* **B at P512:** untouched by construction (M = 512 ≤ step); B P512 G64
  ≈ A′ P512 G64 ≈ #225's 727.3 / 55.17 up to drift.
* **If B P1024 still dies with `0x80000600`** at a 512-row call: the
  staging classes were not the cause (plan §5); B stays VOID, Bfb stays
  the P1024 hybrid of record, and the next lever is address space.
* `heap_kib` should be #225's 75 776; another value means the arena tails
  were filled differently — recorded beside the cell.

   staged. Otherwise copy `/local/mnt/workspace/htp_moe/236/` to the farm
   machine (≈ 260 MB incl. the sidecar) — or rebuild there:
   `git fetch && git checkout htp/236-qkv-chunks`, `source
   tools/htp/env.sh`, `export ANDROID_NDK=$HOME/android-ndk-r30`, `ninja -C
   builddir && ninja -C builddir install`, `(cd Applications/CausalLM &&
   ./build_android.sh --htp --cache)`, then `bash
   docs/measurements/236-stage.sh "$PWD" /local/mnt/workspace/htp_moe/236
   <model dir> /local/mnt/workspace/htp_moe/225` (it takes the skels from
   that machine's #225 set, so A′ and B share the skel bytes). Either way:
   ```
   cd /local/mnt/workspace/htp_moe/236 && md5sum md5.txt   # 1525094e5988aa9eb031b9a6698892b7 (a rebuild differs: paste it under Notes)
   md5sum -c md5.txt | grep -vc ': OK$'                      # 0
   ```
2. **Runner and extras** (already done on this workstation):
   ```
   W=/local/mnt/workspace/htp_moe/236; mkdir -p $W/extra
   cp docs/measurements/236-run.sh $W/run_236.sh; cp tools/htp/loop_check.py $W/extra/
   ```

   `/local/mnt/workspace/htp_moe/225` on the farm machine, or set
   `A225=<dir>`; without it A′ is skipped and the loop / text lines have no
   CPU reference beside them.
3. The unit already holds `models/q40-qs4cx-wh/` and the sidecar from #225
   (the runner checks the sidecar md5 and pushes it only if it differs).
   `adb devices` shows exactly one unit; note its serial and SoC.

   ```
   bash /local/mnt/workspace/htp_moe/236/run_236.sh <serial>          # Q=1 bash … adds the optional Q run
   ```

   It checks both sets against their `md5.txt`, pushes B to `…/causallm/s236`

   (P1024 G64, P512 G64), B P512 G64, B P1024 G64 r1, cool, r2, G512,
   G1024, [Q], the profile. On `STOP` (stale skel `0x8000040e`, unit
   gone, md5 mismatch) reboot and run the same command; it resumes. **A
   VOID is not a STOP.**
5. Expected lines per run: `prefill: <P> tokens, … TPS`, `generation: <G>
