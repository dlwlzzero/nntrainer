[layers] Let recurrent cells declare their output lifespan instead of being named

NetworkGraph::finalizeContext() and refinalizeContext() compared each node's
getType() against RNNCellLayer, LSTMCellLayer and GRUCellLayer and, on a
match, overwrote the lifespan of every output the layer had requested with
FORWARD_GRAD. The graph was hardcoding three layer classes, and what those
layers asked for in finalize() was silently replaced.

How long a layer's outputs must live is a property of the layer, and
InitLayerContext already lets it say so. InitLayerContext::setOutputDimensions()
gets an overload that takes the lifespan to apply to every output; the
existing one-argument version now delegates to it with outSpec()'s own
default, so its 100+ existing callers keep their old behaviour. RNNCell and
GRUCell call the new overload: both have a single output named "out", the
default setOutputDimensions() already used. LSTMCell keeps its explicit
outSpec() calls, since its two outputs use distinct names
("output_hidden_state", "output_cell_state") that the name-less overload
cannot express. Its hidden state output declared FORWARD_FUNC, but the
graph always overwrote it, so that declaration never took effect; it now
declares FORWARD_GRAD, the lifespan the output has had all along, like the
cell state output next to it. The two overwrite blocks in NetworkGraph and
the three cell headers it included only for them go away.

No behaviour change. Every output of the three cells is still requested
with FORWARD_GRAD for its variable and CALC_GRAD_DERIV for its gradient,
with the same names as before. Each of the three type strings is defined by
exactly one class, with no subclass in tree. A cell cannot be
time-distributed either: TimeDistLayer finalizes its inner layer with one
input, and the cells require two or three.
unittest_layers_recurrent_cell_lifespan.cpp checks the declared output
specs of all three cells.

### Summary

- `NetworkGraph::finalizeContext()` / `refinalizeContext()` no longer match `RNNCellLayer` / `LSTMCellLayer` / `GRUCellLayer` by type name to overwrite their output lifespan with `FORWARD_GRAD`. The three cells declare it in `finalize()` instead, and three cell includes leave `network_graph.cpp`.
- `InitLayerContext::setOutputDimensions()` gets a `(out_dim, ls)` overload. RNNCell and GRUCell declare their single `"out"` output through it. LSTMCell keeps its explicit `outSpec()` + `requestOutputs()` calls, since its two outputs use distinct names the name-less overload cannot express.
- LSTMCell's hidden state output declared `FORWARD_FUNC`, which the graph always overwrote. It now declares `FORWARD_GRAD`, the lifespan it has had all along. Whether `FORWARD_FUNC` was the original intent is left out of this PR.
- No behaviour change:
  - Every output of the three cells is still requested with `FORWARD_GRAD` (variable) / `CALC_GRAD_DERIV` (gradient), with the same names.
  - The existing one-argument `setOutputDimensions()` callers (100+ across the tree) are untouched; the new overload is purely additive.
  - Each type string is defined by exactly one class, with no in-tree subclass.
  - A cell cannot be time-distributed: `TimeDistLayer::finalize()` gives the inner layer one input, and the cells require two or three.
- Tests:
  - `nntrainer_RecurrentCell/OutputLifespan` in `unittest_layers` checks the declared output lifespans of rnncell, grucell and lstmcell; it fails on `main` and passes here.
