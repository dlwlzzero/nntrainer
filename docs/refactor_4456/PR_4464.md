> - **RoPE를 먼저** 합니다. ComputeOps에 이미 `compute_rotary_embedding_value`가 부분적으로 있으니 whole-op `rope()` virtual로 확장합니다. CPU, OpenCL(`rope_inplace_f16_cl`), CUDA(`cuda_rope`) 세 구현을 모을 수 있습니다.

**AI 응답:**

> `mha_core.cpp`의 백엔드 선택을 레이어 밖으로 빼서, 레이어는 메서드만 부르고 실제 백엔드는 context가 고르게 만드는 계획입니다. 단계 0~5로 나뉩니다.
>
> ## 목표 구조
>
> ```cpp
> // mha_core.cpp: 백엔드를 모르는 코드
> q.getOps()->rope(...);
> q.getOps()->kv_cache_write(...);
> q.getOps()->attention(...);
> ```
>
> - 레이어의 engine 설정(cpu / gpu / cuda / htp)에 따라 `getOps()`가 `CpuComputeOps`, `ClComputeOps`, `CudaComputeOps`, `HtpComputeOps` 중 하나를 돌려줍니다.

<details><summary>[ComputeOps] Add a rotary_embedding whole-op</summary><br />

[ComputeOps] Add a rotary_embedding whole-op

RoPE has no ComputeOps entry, so the one layer that needs it,
causallm::MHACoreLayer, calls the CPU kernel directly and selects its
OpenCL and CUDA arms with preprocessor and environment branches inside the
layer. ARCHITECTURE_REFACTOR.md lists the missing virtual as what blocks
moving those arms behind the op table (#4451).

Add ComputeOps::rotary_embedding(in, out, head_dim, table, start_pos,
rotate). It rotates every head_dim-wide head of each row in the
rotate-half layout, with height index h at absolute position
start_pos + h, and writes FP32 (in place or not) or fp16 bits, which is
how a layer writes rotated keys straight into an fp16 KV cache. With
rotate false it only copies or converts, the value side of that write.

The table is passed as a RotaryTable: cos and sin as
[positions, head_dim / 2] rows behind stable pointers. That is the form
the device kernels already consume (rope_inplace_f16_cl's LUT, the CUDA
upload), and the CPU kernels read only the first half of each row, so one
layout serves every backend and a device table can cache its upload by
pointer.

CpuComputeOps implements it with compute_rotary_emb_value, row by row,
exactly as the layer's host loop did, plus a bounds check on the table
rows. CudaComputeOps inherits it, and the HTP table is the CPU table
itself. ClComputeOps delegates
to the CPU table for now: the device RoPE is still chosen inside the
layer, which settles the queue before it reaches the host path, so
nothing changes for the OpenCL engine until that arm moves here. The base
default throws, like every other whole-op.

FP32 input only. The FP16-input host kernel exists only in the ARM
backend, so taking it into the core table needs an arch guard; it comes
with the FP16 path of the layer, where it can be checked on ARM.

Tests in unittest_compute_ops_dispatch: dispatch through an attached
table against the rotate-half formula, the fp16-bits write with and
without rotation, and the table bounds check.
