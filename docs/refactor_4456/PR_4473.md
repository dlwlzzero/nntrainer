### Summary

- **Bug.** On `NNTR_ENGINE=gpu` with `NNTR_MHA_GPU=1`, an attention layer with FP32 activations and no RoPE (`rope_theta=0`, `use_gemm_attention=true`) attends over a wrong KV cache. `attention_fp32_on_device()` narrows Q/K/V to FP16 planes with device kernels and does not drain them, because the device arms read them on the same queue. The no-RoPE branch of `one_batch_incremental_forwarding` is a host reader of K and V (it writes the cache on the host) and did not map the planes first, so it copied their stale bytes into the cache.
- **Fix.** The no-RoPE branch calls `settle_act_stage_for_host()` after `lower_kv()`, exactly as the host RoPE fallback does. One call, under `ENABLE_OPENCL`.
- **Blast radius.** Only the gpu engine, only FP32-activation layers without RoPE. BERT is such a model: `bert_transformer.cpp` defaults `rope_theta` to 0, sets `use_rope=false` and `use_gemm_attention=true`, so BERT with FP32 activations on `NNTR_ENGINE=gpu` with `NNTR_MHA_GPU=1` reaches this branch and its attention output changes with this fix (it read a stale cache before). FP16-activation runs and the cpu engine are unaffected. (An earlier version of this description said no model reaches the path; the bot review corrected that.)
- **Regression test (bot review).** The first commit adds a device mode to `unittest_mha_core`: with `NNTR_ENGINE=gpu` in an `-Denable-opencl=true` build on a machine with an OpenCL device, every case runs the same steps against the same reference with its inputs, output and KV caches in the gpu context's shared virtual memory and with the layer's device arms on (`NNTR_MHA_GPU=1`, `NNTR_MHA_GPU_DECODE=1`, set by the test before the layer latches them), held to 1e-2 since the device arms compute in fp16. Without an OpenCL build or a device the cases skip; the host mode is unchanged. `no_rope_gemm` in that mode is the regression test for this fix. It is device-only until an OpenCL runner exists: no CI job builds `-Denable-opencl=true` together with `-Denable-transformer=true`, so CI neither compiles nor runs this path.
