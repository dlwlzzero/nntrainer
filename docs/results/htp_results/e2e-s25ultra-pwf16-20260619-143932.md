# HTP e2e 결과 (pwf16 / dotFloat32Float16) — S25 Ultra (V79)

- **일시(date/time):** 2026-06-19 14:39 KST
- **단말:** Galaxy S25 Ultra (SM-S938N), Snapdragon 8 Elite (SM8750, `sun`/`pa3q`), Hexagon **V79**, arm64-v8a, Android 15, ADB `R3CY205ZMND`
- **DSP_ARCH:** **v75** skel (prebuilt 재사용, `build_htp/libhtp_ops_skel.so`. V79 HW는 v75 skel을 하위호환 실행: vN skel은 HW ≥ vN 필요 → v75 ≤ v79 OK)
- **Hexagon SDK:** 6.0.0.2
- **브랜치 / 커밋:** htp_libs_integration @ 5b226f58
- **경로:** `FloatTensor::dotFloat32Float16` → HMX 커널 `hmx_mat_mul_af32_pwf16_of32` (**pwf16**, FP32 activation / pre-permuted FP16 weight / FP32 output)
- **모델:** Qwen3-0.6B, FC(q/k/v/o/gate/up/down)=HMX 32×32 tile-permuted FP16, embed/norm/q_norm/k_norm=FP32, **lm_head=tied(embed_tokens 공유, FP32)**, 28 layers. weight bin 1,814,560,768 bytes.
- **실행자:** j2z0.lee

## 핵심 변경 (이번 작업)

1. **pwf16 오프로드 가드 완화** (`nntrainer/tensor/float_tensor.cpp:1063`, commit 60c38822):
   동작 중인 pwqk0 가드와 동일하게 `trans_in` 검사 제거. CausalLM FC는 모두 `trans_in=false`로
   `dot()`를 호출하므로 기존 `trans_in==true` 요구가 pwf16 오프로드를 막고 있었음.
2. **tied-embedding 수정** (`nntr_config_hmx.json` + `weight_converter_hmx.py`, commit 5b226f58):
   Qwen3-0.6B는 `tie_word_embeddings=true`. lm_head는 `shared_from=embedding0`로 `embedding0:Embedding`
   weight를 공유하면서 `weight_dtype=LMHEAD_DTYPE`로 요청. HMX config가 `embedding_dtype=FP32`인데
   `lmhead_dtype=FP16`이라 같은 텐서를 두 dtype으로 요청 → `TensorPool::requestOrExtend`
   ("tensor dimension mismatch for embedding0:Embedding")로 토큰 생성 전 크래시. `lmhead_dtype`을
   FP32로 맞추고(공유 embedding과 동일), 변환기는 tied일 때 lm_head를 기록하지 않도록 게이트(동작
   중인 Q4_0 변환기 `weight_converter_htp.py`와 동일). pwf16 목표(FC FP16 오프로드)는 그대로 유지.

### 오프로드 입증 (정확성 = DSP 실행의 직접 증거)

이 config는 FC weight를 **HMX 32×32 tile-permuted FP16**으로 저장한다. pwf16이 DSP로 오프로드되어야만
HMX 커널이 퍼뮤트 레이아웃을 올바르게 소비하여 일관된 출력이 나온다. CPU 폴백은 퍼뮤트 바이트를
row-major로 오독하므로 **출력이 깨진다**. 따라서 동일 모델/바이너리로:

- **HTP (libhtp_ops.so 로드):** 일관된 영어 출력
  > "A large language model (LLM) is an AI system designed to understand and generate human language..."
- **CPU 폴백 (libhtp_ops.so 제거):** 완전한 토큰 노이즈
  > "Flag帷ñeipse dame Norris puesísimoísimoísimoมาísimoalthoughísimo… Dominic … CPPUNIT …"

→ HTP 경로의 일관된 출력은 **pwf16 HMX 커널이 Hexagon V79 DSP에서 실제로 실행되었음**을 결정적으로
입증한다(CPU 폴백이 같은 퍼뮤트 weight로 garbage를 내므로).

## 성능 (동일 단말·동일 pwf16 모델·동일 바이너리)

| 경로 | prefill TPS (tok) | generation TPS (tok) | total | peak RSS |
|------|-------------------|----------------------|-------|----------|
| **HTP (pwf16 on V79 DSP)** | **59.21** (18, 304 ms) | **11.96** (309, 25,847 ms) | 26,202 ms | 3,168,044 KB (~3.02 GB) |
| **CPU 폴백** (libhtp 제거, 출력 깨짐) | 29.75 (18, 605 ms) | 2.87 (512, 178,166 ms) | 178,826 ms | 3,142,440 KB |

> ⚠️ CPU 폴백 행은 퍼뮤트 weight를 오독하여 **출력이 깨지지만**(따라서 EOS 없이 512 토큰 cap까지
> 생성), 동일한 matmul 차원/연산량을 수행하므로 **백엔드 속도 비교용으로는 유효**하다.
> pwf16 HTP는 동일-weight CPU 대비 **generation ~4.2×(11.96/2.87), prefill ~2.0×(59.21/29.75) 빠르다.**

### pwqk0(Q4_0) 결과와의 비교 (중요한 정정)

| 경로 | prefill TPS | gen TPS | 비고 |
|------|-------------|---------|------|
| **pwf16(FP16) HTP** @5b226f58 | 59.21 | **11.96** | 본 측정 |
| pwqk0(Q4_0) HTP @685646fc | 5.21 | 0.30 | per-call x4x2 repack **포함** (17356cbb 이전) |
| pwqk0(Q4_0) CPU 폴백 @685646fc | 144* | 12.42 | (*18-token 측정 노이즈) |

> **이전 결론("per-op FastRPC 오프로드는 CPU 대비 ~42× 느림")은 부분적으로 정정이 필요하다.** 그
> 측정(e2e-s25ultra-20260619-112938.md, @685646fc)은 **매 호출 Q4_0→x4x2 repack**(이후 17356cbb에서
> 제거)을 포함하여 호출당 ~17ms를 소모했다. pwf16 경로에는 그 repack이 없으며, 호출당 비용이
> ~0.43ms(83.6 ms/token ÷ 196 calls)로 떨어져 **per-op 오프로드 자체는 0.6B FP16에서 CPU보다
> 빠르다.** 즉 이전의 큰 회귀는 RPC 구조가 아니라 per-call repack 병목이 지배적이었음을 시사한다.
> (단, pwf16 HTP gen 11.96 TPS는 CPU **Q4_0** 폴백 12.42 TPS와 동등 수준이다 — CPU FP16 커널이
> 특히 느린 것도 4× 격차에 기여한다.)

## 실행 메모 (재현 시 주의)

- **`ADSP_LIBRARY_PATH` 구분자는 세미콜론(`;`)** — 콜론 사용 시 `htp_ops_open`이 `0x80000406`
  (AEE_EUNABLETOLOAD)로 실패. 예: `'/data/local/tmp/nntrainer/causallm;/vendor/lib/rfsa/adsp;/vendor/dsp/cdsp'`.
- 단말 배치: 호스트 libs(`libnntrainer.so`(가드 수정+HTP 빌드), `libcausallm_core.so`,
  `libccapi-nntrainer.so`, `libc++_shared.so`, `libhtp_ops.so`) + DSP skel(`libhtp_ops_skel.so`)을
  `LIBDIR`에, `LD_LIBRARY_PATH=LIBDIR`, `ADSP_LIBRARY_PATH`에 LIBDIR 포함.
- 모델 디렉터리의 config 파일명은 `nntr_config.json`이어야 한다(`main.cpp:340`). HMX config는
  `nntr_config_hmx.json`을 그 이름으로 push.
- **tied 모델 핵심:** `lmhead_dtype`은 `embedding_dtype`과 같아야 한다(lm_head가 embedding weight를
  공유). 불일치 시 finalize 단계에서 dimension mismatch.
- **배포 bin 주석:** 본 측정의 배포 bin(1,814,560,768 bytes)은 변환기 수정 전 생성본이라 tied인데도
  말미에 lm_head FP16(~311MB)을 포함한다. 로더는 오프셋 기반이라 tied lm_head는 graph weight를
  만들지 않아 이 말미 바이트는 **읽히지 않는다**(무해, 검증 완료). 수정된 변환기로 재생성하면 bin은
  1,503,395,840 bytes가 된다.
