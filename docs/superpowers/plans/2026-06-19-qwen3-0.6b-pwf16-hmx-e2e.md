# qwen3-0.6b pwf16(dotFloat32Float16) HMX e2e Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** S25 Ultra(V79)에서 qwen3-0.6b가 `FloatTensor::dotFloat32Float16` → HMX `hmx_mat_mul_af32_pwf16_of32`(pwf16) 경로로 실제 Hexagon DSP에 오프로드되어 동작하도록 만들고 e2e(prefill/generation TPS, peak RSS)를 측정·기록한다.

**Architecture:** pwf16 경로는 IDL/host/DSP 커널/런타임 staging까지 이미 완비됨. 유일한 차단 원인은 `float_tensor.cpp:1063`의 오프로드 가드가 `trans_in==true`를 요구하는데 CausalLM FC projection은 모두 `trans_in=false`로 호출한다는 점. 동작 중인 pwqk0 가드와 동일하게 `trans_in` 검사를 제거하면 오프로드가 활성화된다. HTP libs는 변경 없이 prebuilt 재사용하고 `libnntrainer.so`만 재빌드한다.

**Tech Stack:** C++ (nntrainer FloatTensor), meson Android cross-build(`-Denable-htp=true`), ndk-build(`ENABLE_HTP=1`), Hexagon SDK 6.0.0.2 prebuilt skel(v75), Python weight converter, adb.

git commit -F - <<'EOF'
[HTP] enable pwf16 offload by dropping trans_in guard in dotFloat32Float16

CausalLM FC/Linear projections call dot() with trans_in=false, but the
pwf16 (FP16 weight / FP32 act) offload guard required trans_in==true, so
the path never reached the HMX kernel and fell back to CPU. With the
offline converter storing tile-permuted FP16 weights, the CPU fallback
also misreads them, corrupting output.

Drop the trans_in requirement to match the working pwqk0 guard. The
kernel computes C = A * W and the converter already transposes HF [N,K]
to [K,N], so no runtime transpose is needed.

Signed-off-by: j2z0.lee <j2z0.lee@ax.samsung.com>
