# 설계: qwen3-0.6b pwf16(dotFloat32Float16) HMX e2e on S25 Ultra

- **일시:** 2026-06-19
- **브랜치:** htp_libs_integration
- **단말:** Galaxy S25 Ultra (SM-S938N), Snapdragon 8 Elite, Hexagon **V79**, ADB `R3CY205ZMND`
- **작성자:** j2z0.lee

## 1. 목표

S25 Ultra(V79)에서 qwen3-0.6b 모델이 FP16 weight / FP32 activation 경로
(`FloatTensor::dotFloat32Float16` → HMX 커널 `hmx_mat_mul_af32_pwf16_of32`, 이하 **pwf16**)로
**실제 Hexagon DSP에 오프로드**되어 동작하도록 만들고, e2e 성능(prefill / generation TPS, peak RSS)을
측정한다. 결과는 기존 Q4_0(pwqk0) 결과 문서와 동일한 포맷으로 기록한다.

대상 연산은 **pwf16(dotFloat32Float16)** 우선. dotFloat(wf16, FP32 weight 런타임 변환) 경로는 범위 밖.

## 2. 현황 분석 (코드 검증 완료)

### 2.2 핵심 차단 원인 — `trans_in` 가드 불일치
`float_tensor.cpp:1063` (pwf16 오프로드 가드):
```cpp
if (!trans && trans_in && beta == 0.0f && (K % 32 == 0) && (N % 32 == 0)) {
```
- CausalLM의 모든 FC/Linear projection(q/k/v/o_proj, gate/up/down, lm_head)은
  `input_.dot(weight, hidden_, false, false)` 호출 → **`trans_in = false`**
  (`fc_layer.cpp:217-219, 281`, `layers/lm_head.cpp:154`, `layers/shared_fully_connected_layer.cpp:112,133,159`).
- 따라서 `trans_in` 조건이 **항상 거짓** → pwf16 블록 진입 불가 → CPU 폴백.
- 반면 동작 중인 pwqk0 가드(`float_tensor.cpp:1237`)는 `K%256==0 && N%32==0`만 검사하고
  **trans_in을 보지 않음**. 그래서 동일한 FC 호출로도 Q4_0 e2e는 정상 동작했음.

### 2.3 추가 위험 — CPU 폴백 시 출력 손상
변환기는 32정렬 weight를 **타일-퍼뮤트된 FP16**로 저장한다. pwf16이 오프로드되지 않고 CPU
`shgemm`으로 가면 퍼뮤트 바이트를 row-major로 해석하여 **결과가 틀린다.** 즉 이 config에서는
HTP 오프로드가 정확성의 전제조건이며, 가드 수정은 성능이 아니라 **정확성 이슈**다.
(비정렬 weight는 변환기가 plain `[N,K]` FP16으로 저장하므로 CPU 폴백이 정상 — `weight_converter_hmx.py:128-142`.)

## 3. 해결 설계

### 3.1 핵심 변경 (최소 수정)
`nntrainer/tensor/float_tensor.cpp:1063`
```cpp
// 변경 전
if (!trans && trans_in && beta == 0.0f && (K % 32 == 0) && (N % 32 == 0)) {
// 변경 후 — pwqk0와 동일하게 trans_in 비검사. 커널은 C[i,j]=Σ_l A[i,l]·W[l,j] (전치 불필요)
if (!trans && beta == 0.0f && (K % 32 == 0) && (N % 32 == 0)) {
```
- 근거: 변환기가 HF `[N,K]`를 `w.T`로 `[K,N]`로 전치 후 타일-퍼뮤트(`weight_converter_hmx.py:120-129`)하므로
  런타임에서 추가 전치가 필요 없다. pwqk0가 동일 전치 관례로 정상 동작하는 것이 선례.
- `!trans && beta==0`는 유지(activation staging·커널이 비전치 활성화·무누적을 가정).

### 3.2 빌드 영향 범위
- `float_tensor.cpp`는 **`libnntrainer.so`**에 컴파일됨 → `libnntrainer.so`만 재빌드(enable-htp).
- **HTP libs(`libhtp_ops.so`, `libhtp_ops_skel.so`)는 변경 없음** → prebuilt 재사용.
- CausalLM jni의 prebuilt `libnntrainer.so`를 교체 후 앱 재링크/배포.

### 3.3 모델 산출물
- **weight bin:** `weight_converter_hmx.py`로 `qwen3-0.6b_hf` → `nntr_qwen3_0_6b_hmx_w16a32.bin`
  (FC=tile-permuted FP16, embed/norm/q_norm/k_norm=FP32, lm_head=permuted FP16).
- **config 정리:** 현재 `res/qwen3/qwen3-4b/`에 잘못 위치한 `nntr_config_hmx.json` /
  `weight_converter_hmx.py`를 `res/qwen3/qwen3-0.6b/`로 이전·정리하여 기존 Q4_0 설정과 공존.
  - nntr_config(hmx): `model_tensor_type="FP16-FP32"`, `fc_layer_dtype="FP16"`,
    `lmhead_dtype="FP16"`, `embedding_dtype="FP32"`, `model_file_name="nntr_qwen3_0_6b_hmx_w16a32.bin"`.
  - 기기 배포 시 파일명은 main.cpp가 요구하는 `nntr_config.json`이어야 함(`main.cpp:340`).
  - `tokenizer_file` 절대경로가 기기 모델 디렉터리와 일치하도록 확인.

## 4. 측정 절차 (기존 Q4_0 결과 문서 재현)

1. `libnntrainer.so`(가드 수정본) + prebuilt `libhtp_ops.so`/`libhtp_ops_skel.so` + 호스트 libs를
   `LIBDIR`에 배치, `LD_LIBRARY_PATH=LIBDIR`.
2. `ADSP_LIBRARY_PATH`는 **세미콜론(`;`) 구분자**로 LIBDIR + `/vendor/lib/rfsa/adsp` + `/vendor/dsp/cdsp`.
   (콜론 사용 시 `htp_ops_open`이 `0x80000406` AEE_EUNABLETOLOAD로 실패.)
3. 모델 디렉터리(config.json/generation_config.json/tokenizer*.json/nntr_config.json/weight bin) push.
4. `nntrainer_causallm <model_dir>` 실행.

측정 출력(`models/causal_lm.cpp:645-653`): `prefill: N tokens, ms, TPS` / `generation: ...` /
`total: ms` / `peak memory: KB`.

## 6. 범위 밖 (Out of scope)

- per-op FastRPC 오버헤드 구조 최적화(호출 병합/배치, prefill-only 오프로드 등) — 별도 작업.
- dotFloat(wf16, FP32 weight 런타임 변환) 경로 활성화.
- 다른 모델 크기(qwen3-4b 등) 측정.

## 7. 리스크 / 미해결 사항

- 가드 완화 후에도 결과 e2e는 (기존 Q4_0 분석대로) per-op RPC 오버헤드로 **CPU 대비 회귀**일 가능성이 높음.
  본 작업의 성공 기준은 "pwf16 경로가 정확히 동작하고 e2e가 측정됨"이며, 성능 회귀 여부는 측정 결과로 기록.
- 가드 완화는 pwf16 외 다른 dotFloat32Float16 호출(비-HTP 빌드/비정렬)에는 영향 없음
  (K/N 32정렬 + HTP 심볼 로드 + handle 유효 조건이 추가 게이트로 유지됨).
