# M4–5: e2e 통합·정확도 검증·성능

[← 개요](00-overview.md)

목표: 디바이스 1레이어 → 전체 모델, 3-way 정확도 통과 (M4) → DMA 더블 버퍼링·HAP_power 튜닝, TPS 측정 (M5).

## 정확도 검증 (3-way 기준선)

"양자화 손실 vs 커널 버그" 분리가 목적:

```
① 원본 fp32 (CPU)        ← 진실 기준
② fake-quant fp32 (CPU)  ← 가중치에 quant→dequant 왕복만 적용, 나머지 fp32 ([03] 참고)
③ DSP 실행
```

- ①vs② = 순수 양자화 손실 (perplexity 증가 <1% 기대, 초과 시 양자화 설계 재검토)
- ②vs③ = 커널 구현 오차 (작은 허용 오차 내, 초과 시 커널 버그)
- 지표: 고정 프롬프트에서 토큰별 logits 상대 오차·top-1 일치율, 소규모 텍스트 perplexity

**발산 국소화:** 실행기 디버그 모드 — op-list를 인덱스 i까지만 실행하고 중간 활성화를 IO 버퍼로 반환. ②의 같은 지점과 이진 탐색 비교로 첫 발산 op 특정(~451 op → 비교 ~9회).

## 디바이스 테스트 (8 Elite)

- 3-way 정확도 하니스 + 발산 op 이진 탐색
- 성능: prefill/decode TPS, 토큰당 RPC 횟수(=1) 확인

## 성능 (M5)

**감각치:** decode는 0.6GB/토큰 읽기 — 실효 대역폭 ~40GB/s 가정 시 이론 상한 ~60 TPS대(실측은 그 아래). 기존 0.16 TPS 대비 수백 배 영역.

**튜닝 항목:**
- DMA 더블 버퍼링(계산과 가중치 스트리밍 중첩, [02](02-hvx-kernels.md)) 실측 검증
- `HAP_power` DCVS·클럭 설정
- prefill 청크 크기(예: 128) 스윕

decode 상한 돌파는 커널 튜닝이 아니라 읽기량 축소(Q4 가중치)나 M>1 기법의 영역 — 범위 외 후속 작업.
